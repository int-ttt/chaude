## (a) dispatch rule
1. where: 2절 + 9절 Q1. change: fix the process model before anything else. default = one chaude process is the dispatcher; each client = one `claude` child (stream-json stdin, existing Session/rotate/draining/metrics code). "message to client" = write to that child's stdin, read only at its next turn (matches 2절-4). independent user-opened terminals cannot be dispatched to; list as rejected alternative. Q1 then shrinks to "spawn flags + inbox format".
2. where: 4절. change: `model: opus` cannot tell design client from opus exec client (3절). add classifier field `target: design|exec` (kind=design/judgment/repeated-failure/'opus로' design request -> design; else exec). dispatcher maps (target, model) -> client; classifier never picks client ids.
3. where: 3절 opus exec client. change: conflicts with DECISIONS:40(1) "Opus main only for design turns" and DECISIONS:39 (Opus only for design). drop it as default; Bash-heavy work -> sonnet exec; opus exec client only when the user forces 'opus로' for an exec task. mark as user decision if kept.
4. where: 4절 + 8절. change: specify the exact dispatch payload (one block, prepended to the child input):
   `[dispatch] id: <route-id>` / `design: <abs path | none>` / `result: <abs path assigned by dispatcher>` / `task: <user prompt verbatim>` / `classifier: <one-line task summary>`.
   reasons: user prompt verbatim (classifier `task` is terse and loses detail); result path assigned up front so the dispatcher knows which file to poll (6절 file-state check needs a known path).
5. where: 4절, 8절 "파일이 없으면 작업 한 줄만". change: design file lookup rule missing. add registry `topic -> design file path` (written by dispatcher when the design client saves a plan; route-log entry). and: if target=exec, size large, and no design file exists -> route to design client first, then dispatch exec when the design file appears (exists + size>0 + stable 2s). this blocks the expensive misclassification direction (8절, per-prompt analysis 방향 1).
6. where: 4절 reuse rule. change: (i) reuse threshold must be per model: haiku `ctx < 80k - margin` (e.g. 60k), sonnet/opus `ctx < 240k`; current single 240k never applies to haiku. (ii) busy target (mid-turn): queue in that client's inbox (FIFO, delivered at next turn); do not open a duplicate unless Q4 allows. (iii) multiple same-model clients: pick same topic/files, then most recent lastUsed. (iv) follow-ups ("이어서", "그걸로", same topic) go to the client that handled the previous task of that topic without a model change, since context loss is the real cost of moving (item 12).
7. where: 4절 ack line. change: "직전 클라이언트" is ambiguous with concurrent clients. define = client whose reply the user saw last (last rendered reply), not last dispatched.

## (b) keep/end per client
8. where: 5절 + 9절 Q2. change: make the Opus keep/end judgment a pre-recorded intent, not a call. design client writes `## clients` in its design file during normal design turns: `<client-id|model+topic>: keep | end-after-result`. at last-main-request+3570s the harness reads it and acts deterministically. no extra Opus turn, no waiting on an async reply. this merges 정정 3 (Opus decides) and DECISIONS:23 (59:59 deterministic). missing intent -> end (current fallback).
9. where: 5절. change: state what "keep" can mean past 59:59. idle within 1h costs 0, so ending early saves nothing (it only frees a slot). after 1h the options are: handoff+end (~0.1x ctx + output), ping refresh (billing unknown, on hold), or let the cache expire and keep the process (next use rewrites the whole ctx at 2x; worse than handoff unless ctx is small). so without ping, "keep" past 1h = keep the process for small ctx only (< ~60k, v2 6절 value); otherwise end. the keep/end judgment matters only for (a) ping once allowed, (b) slot cap (Q4). write this down so the judgment is not overvalued.
10. where: 5절 handoff. change: exec clients should end with a deterministic snapshot (0 tokens: design path + result path + route ids + open inbox items), not a warm handoff; their output already lives in result files (6절). warm handoff (LLM-written) only for the design client. this removes N x (0.1x ctx + 5k output) per idle hour, which becomes the main recurring cost with many clients.
11. where: 5절. change: add per-client timer details: base = that client's last main-thread API request (subagent calls do not refresh the main cache); every child spawned with CLAUDE_CODE_PROMPT_CACHE_TTL=1h; 5m fallback (DECISIONS:23 overage) detected per client via usage.cache_creation. concurrent clients burn the shared subscription quota faster -> overage -> 5m TTL more likely; add: when ratestatus shows near-limit/overage, cap to design + 1 exec client and use 290s.

## (e) per-prompt vs per-session (re-check of analysis-per-prompt-classify.md)
12. where: 4절 매 프롬프트 분류 paragraph. change: replace "약해진다(추정)" with an explicit re-derivation:
   - old cost per switch ~8.5만 = new session C0 write 6만 + handoff 2.5만, plus loss of the old 400k cache.
   - separate clients: dispatch to a warm client costs 0 extra and no cache is lost (other clients keep theirs). cold start costs C0 write (~6만) only; handoff 2.5만 disappears (brief = design file path, a few k input read).
   - remaining costs: (1) cold starts, (2) context loss when a follow-up moves to a different client (re-reading files), (3) idle caches that are written but never read again (cleanup cost of item 10, plus cache writes on clients used once).
   - conclusion: per-prompt classification holds (call is a few % and dispatch needs it), but only with reuse-first + max 1 client per model by default. then per-prompt = per-prompt model choice, and the real switching cost = at most one cold start per model per hour window. the old "뒤집히는 가정" (size changes ≥3/session) is no longer the deciding factor; the new deciding factor = number of distinct clients opened per hour.
   - add metric: clients opened/hour, cold-start C0 tokens, idle-ended clients that were never reused (wasted writes).
13. where: 4절 skip list. change: skip classification also for follow-ups bound to the previous topic (item 6-iv) and send them to the previous client; classifier input = new prompt + client table one line per client {id, model, topic, ctx, lastUsed, busy} (~3k, per-prompt analysis 축 5). this table is the upper bound on classifier accuracy, so the dispatcher owns it (deterministic), not a model.
