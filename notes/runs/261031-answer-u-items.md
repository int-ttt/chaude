### U3 반환 검사 훅이 걸릴 도구 이름

1. 무엇을 정하는지: 서브에이전트 호출이 끝난 뒤 결과를 검사하는 자동 실행 스크립트(훅)를 어느 도구 호출에 붙일지 정합니다. 훅의 "matcher"는 어떤 도구 이름에 반응할지 정하는 조건입니다.
2. 계획서 위치: 6절(155행), 13절(218행), 14절.
3. 틀리면 생기는 일 (추론): matcher 이름이 틀리면 훅이 한 번도 실행되지 않습니다. 검사 모드가 log라서 누락 기록도 0건으로 남고, 문제가 없는 것처럼 보입니다.
4. 현재 상태: 보류입니다. 사용자 판단은 없고 구현 단계에서 조사합니다. 사용자 답은 필요하지 않습니다. 검사는 차단하지 않습니다(모드 log, warn, off 중 기본값 log). 선택지는 구현 단계 조사, 지금 조사 의뢰, 훅 없이 진행입니다.

### U4 실행 모드 f의 기본 활성 여부

1. 무엇을 정하는지: 하네스 실행 모드 f(--clients-file 옵션)를 기본 실행에서 켜 둘지 정합니다. 계획서상 이 모드는 --clients-file을 설정했을 때만 살아 있는 자식 프로세스를 띄웁니다. 기본 실행에서 켜지는지는 아직 확인하지 못했습니다.
2. 계획서 위치: 13절(219행), 14절. 7절(168행)도 이 내용을 참조합니다.
3. 틀리면 생기는 일 (추론): 기본 실행에서 꺼져 있는데 켜져 있다고 보고 측정하거나 적용하면, 사용자가 실제로 쓰는 경로와 다른 경로를 대상으로 잡게 됩니다. 계획서 7절은 작업 공간(ws) 필드에 none을 허용해 이 가정에 덜 기대고 있습니다.
4. 현재 상태: 보류입니다. 구현 단계에서 처리합니다. 사용자 답은 필요하지 않습니다. 원하시면 사용, 미사용, 모름 중 하나로 답해 주셔도 됩니다.

### U5 서브에이전트와 프롬프트 캐시 공유 여부

1. 무엇을 정하는지: 서브에이전트가 부모 세션과 프롬프트 캐시(같은 앞부분 입력을 싸게 다시 쓰는 기능)를 공유하는지 정합니다. 결정은 공유하지 않음입니다. 서브에이전트는 자기 결과만 부모에게 전달합니다.
2. 계획서 위치: 1절 원칙(32행), 13절(220행), 14절.
3. 틀리면 생기는 일 (추론): 공유한다고 가정하면 서브에이전트가 부모의 긴 앞부분을 싸게 쓴다고 계산해 절감액을 실제보다 크게 잡게 됩니다.
4. 현재 상태: 결정됨입니다. 절감 계산은 캐시 공유를 전제하지 않습니다. 사용자 답은 필요하지 않습니다.

### U7 summary_ko 필수 검사 가능 여부

1. 무엇을 정하는지: 브리프에 lang: ko라고 적힌 호출의 반환에 한국어 요약(summary_ko, 1~5줄)이 반드시 있어야 하는지, 그리고 훅이 그것을 검사할 수 있는지 정합니다. 계획서상 summary_ko는 메인에게 바로 돌아오는 반환에만 씁니다.
2. 계획서 위치: 2절 반환 규칙 항목(48행), 6절 검사 항목(160행), 14절.
3. 틀리면 생기는 일 (추론): 훅이 브리프 본문을 볼 수 없으면 lang: ko인지 알 수 없습니다. 그러면 summary_ko가 빠진 반환을 잡지 못해, 메인이 사용자에게 전달할 한국어 요약 없이 본문만 받는 일이 생길 수 있습니다.
4. 현재 상태: 보류입니다. 구현 단계에서 확인합니다. 사용자 답은 필요하지 않습니다. 선택지는 검사 보류, 구현 시 확인 후 결정, summary_ko 항상 필수입니다. 참고로 계획서 11절 R1은 summary_ko를 선택 항목으로 적고 있어, 항상 필수로 바꾸면 그 완화 방안과 어긋납니다.

### U8 haiku-prompter 전달문 형식과 해석 확인

1. 무엇을 정하는지: haiku-prompter가 사용자 프롬프트를 opus 세션에 넘길 때의 형식입니다. 결정은 사용자 원문을 그대로 넣고 요약 한 줄을 함께 붙이는 방식입니다. haiku-prompter는 기존 반복 요청 처리 역할을 유지하고, 전달 역할을 추가합니다.
2. 계획서 위치: 2절(42행), 4절 표의 haiku-prompter 행(135행), 6절(162행), 14절.
3. 틀리면 생기는 일 (추론): 해석이 틀렸을 때의 예입니다. 메인 세션이 실제로는 직접 답하는 방식으로 운영되는데, 한국어 존댓말 검사를 haiku-tui 출력에만 걸어 두면 메인의 답변이 검사에서 빠집니다. haiku-tui 에이전트 파일은 아직 없고 구현 단계에서 만듭니다(13절 221행).
4. 현재 상태: 전달문 형식은 결정됨입니다. "사용자 대면 출력은 haiku-tui가 맡는다"는 해석은 사용자 답이 없어 확인되지 않았습니다. 이 부분만 사용자 답이 필요합니다.

사용자께서 답하셔야 할 것은 하나뿐입니다. U8의 해석, 즉 "사용자 대면 출력은 haiku-tui가 맡는다"가 맞는지 아니면 정정이 필요한지 알려 주시면 됩니다.
