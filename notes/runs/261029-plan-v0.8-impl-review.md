## decisions

1. (a) scope: KEEP the cut, KEEP the name 0.8.0.
 - why: new persisted file, 3 new flags, new idle behavior = minor bump by repo convention (0.7.0 = persisted subagent state). Deferring multi-process dispatch is right: it rewrites Repl's single r.sess and Q1 is open.
 - change: CHANGELOG/commit title must not say "multi-client". Wording: `0.8.0: per-model session registry (warm reuse across restarts), idle end at 59:59 inside cache TTL, cache TTL auto-detect`. Multi-process dispatch = 0.9.0.
 - trim: drop `DesignPath` and `ID` from clientRec (no design client in 0.8; model+cwd is the key). States: `live|parked|expired` (who sets open vs idle is undefined in the plan).

2. (b) 1h TTL: do NOT pin by default. Flag `--cache-ttl auto|1h|5m`, default `auto` = set no env.
 - why: research row 12/14/20: in-plan subscription Claude Code already requests 1h for main; in overage it drops main to 5m. A pinned env (bucket env > default in precedence) overrides that drop, so in overage every cache write is 2x on credits. `auto` gives exactly DECISIONS:23's intent (1h in plan, 290s fallback in overage) without the overage cost trap. `1h` remains for an explicit pin. Note in DECISIONS that this replaces the literal "pin" wording of DECISIONS:23 (user OK needed at U8).
 - detection (new pure func, see U2b): effective TTL per main assistant event from `usage.cache_creation`: ephemeral_1h_input_tokens > 0 -> "1h"; else ephemeral_5m_input_tokens > 0 -> "5m"; else keep previous value. Store as r.ttlSeen.
 - fallback if stream-json does not carry `cache_creation`: treat TTL as 5m (290s) until proven 1h. Proof = a main request whose start is > 300s after the previous one and has cache_read_input_tokens > 0 -> set r.ttlSeen="1h". Reason: wrongly assuming 1h resumes cold sessions (full re-write of ctx) and runs the 59:59 handoff on a cold cache; assuming 5m only costs an earlier handoff at cache-read price.
 - gate check U0 (haiku-runner, 1 call): `claude -p --output-format stream-json --verbose "hi"` -> grep `ephemeral_1h_input_tokens` in the assistant event usage. Transcript evidence says yes; stream-json unverified.

3. (c) Q3: close at 59:59, do not keep live. Reopen = new session from snapshot (0.9: + design file path).
 - why: after TTL a live process saves nothing (next use re-writes full ctx at 1.25x/2x) and holds a slot; a new session from handoff/design file is smaller. In 0.8 there is no design client (conductor main is Haiku-fixed), so Q3 only fixes the default recorded for 0.9; `--idle-end 0` = keep live.
 - GAP in plan U5: "close + MarkEnded, LLM 0" loses the context: the next prompt gets a blank session. DECISIONS:23 ("캐시 갱신은 59:59초에 수행") and DECISIONS:19 mean: at the deadline run the existing `r.rotate("idle 3599s")` (handoff runs inside TTL at cache-read price; snapshot held as pendingSnapshot; sent before the next prompt). Then registry row -> expired, ended_reason=idle-3599. Skip if no turns since the last rotation. Fire at most once per lastAPI value (else hourly empty restarts).
 - parked (non-live) rows: no process exists (switchSession closes the child, classifier.go:213), so no timer; expiry is the time check in isWarm only.

4. (d) Q4: adopt "1 design + 1 exec, max 1 per model" as the 0.9 cap; 0.8 = 1 live main child (structural), registry 1 row per (cwd, model).
 - define what counts: live claude children owned by chaude as main/client. Draining old sessions (MaxDrain, default 3) and Task subagents and haikupool workers do NOT count. Write this in DECISIONS with Q4.
 - haikupool: rr.Worker (classifier.go:176-178) keeps priority over the registry for haiku; registry haiku row = main haiku session only.
