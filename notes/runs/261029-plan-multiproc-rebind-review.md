## 1. Rebinding design -> decision: KEEP single-slot + copy-swap, with 4 changes
1a. state split (replaces G2 list). per-child (swap): sess, tracker, Model(r.a.Model), lastCtx, cat, LastAPI, TurnFrom, pendingSnapshot (undelivered snapshot of that child; plan sets "" on bind -> loses a rotate/import snapshot not yet sent), lastRotFail (cooldown belongs to the child that failed), ttlSeen, idle accumulator (r.idle is one shared idleTurn written by every idle reader -> must move to the per-child struct). conversation-level (do NOT swap): tr, files (validateHandoff/buildSnapshot of any child must see files edited by other children; plan swaps them), lastReco, lastReply, notices, draining, rotations, seenTools, pool, rate. per-turn (reset, no swap): delegs, curTask, resumeID.
1b. context gap (missing in plan): a child returned via actUseLive/actResume has not seen turns made while parked. bindChild: if len(r.tr.turns) > c.TurnFrom -> r.pendingSnapshot = deterministic brief of r.tr.turns[c.TurnFrom:] (+ files added since park), header "## While this session was parked", cap 3,000 chars haiku / 6,000 opus,sonnet (DECISIONS overview caps), 0 model tokens. Only set "" when no new turns. TurnFrom = len(r.tr.turns) at park time.
1c. races: idle readers run on their own goroutines; `s == r.sess` read there vs write in route = data race. Allocate the per-child struct (*liveChild) in start(), capture it in the idle closure, mark state with `c.parked atomic.Bool` (set true FIRST in unbindActive, false LAST in bindChild). Fields the idle goroutine writes (LastAPI, idle accumulator) live only on *liveChild under its own mutex; touchMain needs no childSet lookup. Never leave r.tracker nil (tui.go:312/329/378/983 read it every tick from the UI goroutine): unbindActive keeps r.tracker until bindChild/start overwrites it. r.sess nil window: nil-guard tui.go:890 (/status) like localcmd.go:36.
1d. parked child events: plan forbids render but leaves idleFinish -> usageLine (renders) + metrics with r.a.Model/r.lastCtx (wrong child). Parked path: no idleText/usageLine/r.idle; buffer main-thread reply per child; on result log metrics with c.Model/c.LastCtx and queue notice "[parked <model> background reply] <trunc 300>" (notices gets a mutex; today main-goroutine only). can_use_tool from parked child (G1): decideMode; if "ask" -> deny with message "denied: session parked (another model is active)"; never r.ui.ask (would collide with the active turn's prompt). G1 resolved by design, no runTurn change needed.
1e. actStartNew with history: plan says "r.start() + rotate" but r.sess is nil after unbind -> rotate() panics (repl.go:575). Order: extract `makeSnapshot(reason) (snap string, ok bool)` from rotate (handoff turns + validate + withReco, no close/start); for model switch with history and no warm target: snap from the OLD child while still active -> unbindActive+Park -> start() -> r.pendingSnapshot = snap. rotate() itself calls makeSnapshot (behavior unchanged, existing tests guard).
1f. child with no API call (LastAPI zero, e.g. startup haiku child before first routed prompt): Close instead of Park (isWarm would reject it anyway; parking only leaks until sweep).

## 2. State table -> decision: add 2 states + 9 transitions
states to add: draining (alive, in r.draining, not childSet; existing rotate path), dead (process exited, entry still in childSet/registry says live).
transitions missing:
T1 active -> draining | expired: threshold/category/manual/idle rotate (rotate closes or drains r.sess); registry MarkEnded(reason) or State=draining note. plan table only has "모델 전환 -> parked".
T2 parked -> draining: sweepIdle on a parked child with tracker.running()>0 must drain (same as rotate), not Close (plan closes -> kills background agents).
T3 parked -> dead: child exits/crashes (idle reader sees s.lines closed). Set c.dead; sweep/pickChild Take+drop, registry expired "child-exit". pickChild must treat dead as absent (today actUseLive -> Send to dead pipe).
T4 active -> dead (crash mid-turn): registry row stays "live" with a live owner forever (reconcile skips live owners). On next start() for that key Upsert overwrites; on Events error MarkEnded("child-exit").
T5 parked(set, not warm) -> closed: pickChild falls through to the registry row of the SAME session id (OwnerPID == self passes clients check) -> actResume spawns a 2nd process on a session id whose 1st process is alive. Rule: if set has key and !isWarm -> Take; agents running ? drain : Close; then registry decides; never resume a SessionID present in set or draining.
T6 forced kill of harness (kill -9 / SIGHUP from terminal close; Go default for SIGHUP exits without defers; SIGTERM today only interrupts, repl.go:932): children (Setpgid) are not signalled, get stdin EOF, may live on running background agents. reconcile zeroes ChildPID and may mark row parked -> next run resumes while orphan still writes the same session. Fix: reconcile checks pidAlive(ChildPID) first; alive -> State expired reason "orphan-alive" (no resume). Add SIGHUP to signal.Notify -> orderly exit (markInterrupted, closeDrains, CloseAll, registry MarkEnded "harness-exit"). L4 must check `ps` child count after ~20s, not only clients.json.
T7 /clear and import (applyImport): CloseAll parked children + registry expired "clear" (else a later switch revives pre-clear context). /model <name>: keep rotate (DECISIONS) but Take+Close/drain any parked child of the target key first.
T8 start failure rollback: also restore registry row to live and r.a.Model; bind failure on actUseLive (dead child) -> fallback actStartNew with deterministic snapshot.
T9 deadline 0 (--idle-rotate 0, idleDeadline returns 0): isWarm -> never warm, Expired -> every key expired (sweep closes all parked at once). Treat deadline<=0 as "no expiry" in isWarm and Expired.

## 3. v0.7.3 scope -> decision: CONFIRM (live path for model switches only; same-model haiku worker switch keeps Close+--resume), with route reorder
reason: same-model live pool = N haiku processes per cwd, more RAM/orphans, little cache gain (haiku workers are cheap). model switch is where cache reuse pays (opus/sonnet 270k ctx).
required change: plan hooks only classifier.go:183-199, but the haiku branch at :175-179 runs first and calls switchSession (Close) -> L2 "Close 0" fails on sonnet->haiku and opus->haiku; and r.parked[model] (:185) resumes before any live lookup -> returns to sonnet/opus via resume, not live. New order inside switchChild:
  1. target model == r.a.Model: rr.Worker != "" -> existing switchSession (same-model park-resume); else nothing.
  2. target != r.a.Model: old child -> (history? Park : Close); do NOT write r.parked for a live-parked child (avoids double ownership).
  3. target haiku with rr.Worker != "": if set has haiku key, Take + (drain|Close) it; then resume worker (switchSession body minus its Close).
  4. else pickChild: actUseLive -> Take+bind; actResume -> resume; actStartNew -> r.parked[model] resume if present, else start (+snapshot per 1e).
  5. registry nil -> old code path verbatim (TestRouteFallsBackWithoutRegistry).
max live children: one per (cwd, model) = 3 per harness; doc it.

## 4. $3 cap -> decision: harness-side ledger is primary; CLI flag is a backstop; stop BEFORE the next call, plus mid-turn interrupt
fact: CLI has the flag: `claude --help` (2.1.312) shows `--max-budget-usd <amount>` "only works with --print"; chaude children run `-p` (core.go:143) so it applies. C1 = confirmed exists; C3 still open.
why the flag alone is insufficient: it is per process; one task spans 3-4 children (L2) + classifier one-shots (classifier.go:134) + handoff turns + /usage one-shots; likely resets on --resume.
fact: result.total_cost_usd is cumulative per process (metrics 2026-10-29: session 26e84f4e 0.175 -> 0.427 -> 0.490 -> 0.494 -> 0.644 -> 0.736, monotonic). So ledger adds deltas: spent += cur - last[sess]; classifier/usage one-shots add their own total_cost_usd.
stop points (all three):
  S1 pre-call gate (main): before classify and before each Send (user turn, handoff turn): if spent >= cap or spent + est(next) > cap -> refuse, print "[budget] $X / $3 reached, task stopped", Close nothing (children parked normally), metrics stage=budget. est(next) = lastCtx * (cache-read price if warm else cache-write price: 1h 2x, 5m 1.25x input) + 4k output tokens * output price, per-model price table.
  S2 mid-turn: on each main assistant usage event, running estimate += call cost; if spent+running >= cap -> sess.Interrupt() (existing esc path). Overshoot bounded by one API call.
  S3 per-process `--max-budget-usd <cap>` appended to opts.Extra only when the live-test cap is set (flag `--task-budget-usd`, default off), so a runaway child or background agent stops even if S1/S2 miss.
after-only stopping rejected: one cold opus turn at 270k with 1h cache write can cost about $3 alone, so checking after the call can double the cap.
task boundary: ledger resets on each user prompt (task = one L-item prompt); background-agent costs arriving later are charged to the task that started them (via the process delta, which is automatic).
remaining check (replaces C1/C3 experiment): one stream-json child, `--max-budget-usd 0.01`, 2 turns: record result subtype (expected error_max_budget_usd), whether the process exits or keeps accepting input, and whether --resume resets the counter. Cost < $0.05. If the process exits -> S3 child is treated as dead (T3).
note: on subscription login total_cost_usd is a notional price; the cap is still a usable proxy.
