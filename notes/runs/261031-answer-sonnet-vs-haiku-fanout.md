# sonnet 분석·검토 대 opus+다수 haiku 비교 평가

## 1. 직전 작업 평가
- 근거: 계획서(P, 202행)는 선택지 C 채택, L1을 opus-architect 단독+haiku로 하고 sonnet-analyst·sonnet-reviewer를 제거하는 안입니다. 상태는 "계획안, 코드 변경 없음"입니다.
- 완성도: 구조는 갖췄으나 §7의 미결 질문 Q-A~Q-F(추가 삭제, gate, CLAUDE.md 승인, opus 단독 L1 확정 등)는 모두 답이 비어 있어 실행 불가 상태입니다.
- 빠진 점: opus 검토 33건(a 13, b 7, c 9, d 4) 중 치명 3건이 있습니다. (21) archive한 .go가 go test를 깨뜨림, (22) classifyFn 스텁 제거 순서, (23) 에이전트 삭제와 CLAUDE.md 사이 공백입니다. 그 밖에 tui.go, skills, README, haiku-coder.md 참조 누락, D3/D4 사유 뒤바뀜, 가격 구조 불일치(budget.go:94 대 usage_report.go:18)가 있습니다.
- 반려 기록(scope 파일): sonnet 삭제는 2절이 요구하는 L1 종단 3개 중 2개를 없앤다는 충돌이 있었고, 옵션 A/B/C 중 사용자만 정할 수 있다고 적혀 있습니다. 계획서는 C를 채택했으나 A·B 기각 사유와 사용자 확정 기록은 찾지 못했습니다(미확인).
- 신뢰도: 검토 33건은 리뷰어 주장 그대로이며 행 번호는 직접 확인하지 않았습니다. 중간 수준입니다.

## 2. 비용 비교
- 근거 있는 수치: 단가 opus in 4/out 20, sonnet in 2/out 10 ($/MTok, alias 가정, 공식 단가 미검증). 같은 토큰이면 opus가 약 2배(추정).
- 계획서 자체 결론: 절감·증가 방향 모두 미확인, 실측 없이 판단 금지(U1=a), 목표 수치 없음.
- 호출 수: 현 구성은 메인 -> sonnet -> haiku, 안 C는 메인 -> opus -> haiku. 라우터 classifier 호출 1회 제거로 단계 1 감소(계획서 주장). 하위 반환을 opus가 모두 입력으로 받으므로 opus 입력 토큰은 남습니다.
- 리뷰어 제안 상한: haiku 병렬 <=4개/과제, 반환 <=4000자, 응답 <=20회 (제안, 미측정).
- 호출당 토큰·비용 실측: 미측정. 기준선 추출(notes/metrics, LEDGER 최근 7일)은 제안만 있고 아직 안 했습니다.

## 3. 품질 비교 (추론 위주, 실측 없음)
- 판단 정확도: opus가 sonnet보다 높을 가능성이 크나 이 저장소 실측 근거는 없습니다.
- 중간 누락 위험: haiku 다수 병렬은 파일 분할 과정에서 교차 사실이 빠질 수 있고, opus는 반환 요약만 보므로 요약 손실이 누적됩니다. 이번 검토에서 누락 참조가 다수 나온 점이 이 위험을 시사합니다.
- 독립 검토 상실: sonnet-reviewer를 없애면 작성자와 검토자가 같은 opus가 되어 독립성이 약해집니다. 완화책은 재호출 제한(opus 1회)뿐이라 구조적 보완은 없습니다.

## 4. 결론
- 현 시점 권고: 보류 후 측정 우선. 먼저 sonnet 호출당 비용 기준선을 뽑고, 같은 과제를 두 방식으로 한 번씩 돌려 비용과 누락 건수를 비교한 뒤 확정하십시오.
- 근거: 비용도 품질도 실측이 없고, 미결 Q-A~Q-F와 치명 3건이 남아 있으며, 독립 검토 상실은 확실한 손실이지만 절감은 불확실합니다.
- 불확실: 단가 가정, 리뷰어 행 번호, A/B 기각 사유.
