# Review: 261029-plan-three-session-structure.md
기준: 개선점만. 계획 파일은 수정하지 않음. 근거 확인 범위: 계획 전문 + hybrid-design 8-18행 (D1, D2).

1. [사용자 정정 점 번호 순서/위치] 점1-6이 목표 절에서 "각 절에 한 번씩"이라 했으나 점2·점4가 같은 "분류자 흐름" 절에, 점1이 "세션 구성"에 있어 점 번호 순서가 문서 순서(1,2,4,3,5,6)와 다름. 각 점 옆에 "(정정 점 N)" 대신 목표 절에 점→절 대응표 1줄 추가.
2. [점1 의미 변형 위험] "Opus 설계 기획 세션은 항상 존재"는 사용자 원문 인용이 아니라 요약임. 세션 구성 절에 사용자 원문 6점을 인용 블록으로 따로 싣지 않아 "의미 불변" 검증이 불가. 목표 절 아래 원문 6줄을 그대로 붙일 것.
3. [점3 문장 모호] "그 판단으로 각 세션을 유지할지 종료할지 Opus가 결정한다"에서 "각 세션"이 sonnet/haiku 둘 다를 별개로 보는지(세션별 판단) 불명. 점3의 1시간 판단 대상 단위(세션별/모델별)를 명시.
4. [용어 불일치] "설계 세션/설계 기획 세션/Opus 설계 세션", "실행 세션/세션", "개요 파일/설계 파일"이 혼용됨. 하나로 통일(예: Opus 설계 세션, 실행 세션, 설계 파일). 특히 열린 질문 5의 "Haiku 개요 파일"과 데이터 흐름의 "설계 파일"이 같은 파일인지 분리 파일인지 불명.
5. [참조 방식] "분류자 흐름 참조", "hybrid-design D1/(c) 규칙 2-3"에서 "규칙 2-3"은 (c) 내부 번호라 이 리뷰에서 확인 못 함(hybrid-design 40행 이후 미확인). 인용 시 줄 번호로 바꾸고 DECISIONS:NN 도 줄 번호임을 표기에 명시(표기 줄에 "DECISIONS:N = 줄 번호" 추가).
6. [점6 실행 가능성 누락: haiku-scout 호출 형태] 계획에 호출 모습이 없음. 추가할 것: 호출 주체(Opus 설계 세션? 실행 세션? chaude?), 입력(설계 파일 절대경로 + 실행 세션이 필요로 하는 질문), 출력(요약 ≤N줄, 파일 읽기 전용, 원문 붙여넣기 금지). 현재 4단계 "haiku-scout가 읽어 요약 전달"은 누가 호출하는지 없음. haiku-scout는 읽기 전용(Read/Grep/Glob/Bash)이라 설계 파일 쓰기는 Opus 쪽이 해야 함을 명시.
7. [점6과 hybrid-design D2 설명 불균형] 충돌 줄에서 D2("Haiku가 개요 작성/관리, Opus·Sonnet은 검토만")를 폐기 처리하나 열린 질문 5로 다시 미룸. "채택"과 "열린 질문"이 동시에 있어 모순처럼 읽힘. 임시 기본값(예: D2 보류, Opus 작성만 적용) 한 줄로 정할 것.
8. [파일 소유자 누락] 누가 어떤 파일을 쓰는지 표가 없음. 필요한 표: 설계 파일(notes/runs/<YYMMDD>-plan-<topic>.md)=Opus 작성; 분류 프롬프트/답변 전달 사본=chaude(코드)가 기록? 어디에?; 결과 파일 notes/runs/...=실행 세션; metrics=chaude(stage=classify). 점4의 "프롬프트와 답변을 Opus에게 전달"의 전달 매체(세션 입력 메시지 vs 파일)도 미정.
9. [점4 구현 단위 누락] 분류자 "각 모델의 답변"이라는 표현이 분류 1회 호출(DECISIONS:32 유지)과 충돌 가능: "각 모델"이 분류자 모델(sonnet/haiku) 답변인지, 실행 세션 답변까지 포함인지 불명. 열린 질문 2에 이 해석 질문 추가.
10. [코드 영향 범위 누락] status는 "문서만"인데 실행 계획(단계, 변경 파일, 수용 기준)이 없음. 작업 중인 internal/harness/classifier.go, repl.go, tui.go(미커밋 변경) 중 어느 곳이 영향받는지, 순서(hybrid-design D3: 백그라운드 패널 수정 먼저)와의 관계를 1줄이라도 적을 것.
11. [수치 절 정리] 컨텍스트 한도 절의 "충돌 없음 그러나 미정"은 제목과 내용이 어긋남. "일치"와 "정리 필요"로 분리. 또한 270k(전환 기준)와 sonnet/haiku 분류자 컨텍스트 한도 적용 여부 불명.
12. [열린 질문 번호와 본문 연결] 열린 질문 1-6이 본문 "가정" 줄과 1:1 대응하지만 본문에 번호 참조가 없음(예: 가정 → Q1). 가정 줄 끝에 "(Q#)" 추가. 본문 가정 중 "백그라운드 에이전트 draining 유지"(32행)와 "15분 강제 초기화" 건은 Q4에만 일부 반영됨.
13. [검증/수용 기준 누락] 이 문서가 사용자 확인 대기용이라면 확인 순서(우선순위)가 필요. 권장: Q2(Opus 전달 순서/오분류 수정)와 Q4(1시간 vs 15분)를 먼저, Q6은 후순위.

우선 3개: 6 (haiku-scout 호출 형태와 호출 주체), 8 (파일 소유자 표), 2 (사용자 원문 6점 인용으로 의미 불변 검증).
