## 4. 해석 (모두 추정)

1. 사용량은 10-27 이후 폭증했고, 그 원인은 하네스 개발과 테스트입니다. 10-28 하루에 세션 152개가 생겼는데 대부분 claude-harness 하위와 e2e 임시 디렉터리입니다. 일상 사용이 아니라 테스트 부하일 가능성이 높습니다.
2. 작업은 서브에이전트 위임 중심입니다. sidechain 줄이 약 35%이고 sonnet-analyst가 가장 많이 호출되어, 본 세션은 라우팅과 요약을 맡고 실제 작업은 Sonnet/Haiku 서브에이전트가 하는 구조로 보입니다.
3. 모델 비용 구조는 Haiku/Sonnet이 건수의 약 70%이고 Opus는 약 26%입니다. 건수가 아닌 토큰 기준 비용 비중은 이 자료로 계산할 수 없습니다.
4. 컨텍스트는 캐시 읽기 위주라 단가는 낮지만, 10-29의 캐시 생성 증가와 rotate 증가는 세션이 길어져 로테이션이 자주 일어났음을 시사합니다.
5. 가장 활동이 많은 시간은 UTC 01시, 14~15시입니다. KST로는 심야와 밤 시간대가 포함됩니다.

## 5. 불확실한 점

- 비용 합계는 하네스 필드의 합이고 result_* 와 턴 단위 필드가 겹칠 수 있어 이중 집계 가능성이 있습니다(metrics 요약의 자체 경고).
- metrics는 이틀치뿐이라 일/주 추세를 말할 수 없습니다. 트랜스크립트 쪽 비용(cost-state 218건)은 이번에 집계하지 않았습니다.
- 세션 수는 서브에이전트와 테스트 세션이 섞여 있어 사용자가 직접 연 세션 수를 따로 알 수 없습니다.
- 트랜스크립트의 모델 이름이 claude-opus-5와 claude-opus-5-5처럼 별칭으로 나뉘어 있어 같은 모델의 다른 표기인지는 확인하지 못했습니다. 위 비중은 이름 그대로 합산했습니다.
- 타임스탬프 없는 줄 11,384개(약 23%)가 시간 집계에서 빠졌습니다.
- 일자별 표는 UTC 기준이라 KST 날짜 경계와 어긋납니다.
- 도구 사용 수는 assistant 메시지 기준이며 서브에이전트 내부 호출도 포함합니다(별도 분리 안 함).
