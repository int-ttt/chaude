## 1. 범위
v0.8 구현 (최소):
1. 클라이언트 레지스트리 파일 `~/.chaude/clients.json`: 모델별 {id, model, sessionId, state(open|idle|ended|expired), lastUsed, lastCtx, designPath}.
2. 모델별 따뜻한 클라이언트 재사용: parked map 대신 레지스트리 조회(임계값 안 + state=idle|open + 만료 전), 없으면 새로 열기.
3. 3599초 결정론 종료: 마지막 메인 API 요청 시각 기준 3599초 경과 시 해당 클라이언트를 닫고 레지스트리에 state=expired, ended_reason=idle-3599 기록. LLM 호출 0.
4. 1시간 TTL: 자식 env에 `CLAUDE_CODE_PROMPT_CACHE_TTL=1h`(research: env 지원, 5m|1h만 허용). 플래그 `--cache-ttl 1h|5m`(기본 1h), overage 폴백은 5m이면 idle 기준 290초.
5. 버전 0.8.0 + CHANGELOG 항목.

보류 (사유):
- 진짜 다중 프로세스 동시 디스패치(생성/FIFO inbox/바쁨 큐): 활성 자식이 하나인 Repl 구조(r.sess 단일, draining만 병렬) 전체를 바꿔야 하는 5+ 파일 상호 의존 변경이고 Q1(디스패처 모델) 미확인. v0.9 후보.
- dispatch 블록, 결과 경로 폴링, `[clients]` 요약 붙이기(v3 §10 (2)(5)): 다중 자식 이후에만 의미.
- `## clients` 의도 파일 읽기(Q2): Q2 미확인, 기본은 의도 없음=종료라 v0.8 동작과 같음.
- 핑(Q6 과금 미확인), 클라이언트 간 캐시 공유 검증(research: 미검증).
- 설계 파일 선행 규칙: 설계/실행 클라이언트 분리가 선행되어야 함.

## 2. 변경 파일 / 유닛 (유닛 = 파일 1개 + 함수 1개 안팎, haiku-coder 단위)
U1 신규 `internal/harness/clients.go` (+ 상수/타입)
 - type clientRec struct{ID, Model, SessionID, State string; LastUsed time.Time; LastCtx int; DesignPath string; EndedReason string}
 - type clientRegistry (mutex + path), `newClientRegistry(path)`: agentstore.go 패턴(원자적 쓰기 tmp+rename, 파일 없음/깨짐=빈 레지스트리).

 - `(g *clientRegistry) Warm(model string, ctx, limit int, now time.Time, ttl time.Duration) (clientRec, bool)`: state가 open|idle, now-LastUsed < ttl, ctx < limit이면 true. 순수 함수형으로 시계 주입.

U2 `internal/harness/core.go` `cleanEnv`: 시그니처에 ttl 인자 추가(`cleanEnv(compactWindow int, cacheTTL string)`), cacheTTL != ""이면 기존 `CLAUDE_CODE_PROMPT_CACHE_TTL=` 제거 후 추가(AUTO_COMPACT_WINDOW와 같은 패턴). SessionOpts에 `CacheTTL string` 필드, :125 호출부 갱신. 다른 호출부(grep cleanEnv)도 함께.

U4 `internal/harness/repl.go` Repl: 필드 `clients *clientRegistry`, `lastAPI time.Time`. 메인 assistant usage를 받는 지점(idleEvent :217 이후의 main usage 처리와 턴 이벤트 처리)에서 `r.touchClient()` 호출: lastAPI=now, registry.Touch(r.a.Model, r.lastCtx, now). 서브에이전트 이벤트는 제외(isMainEvent).

## 4. 가정과 검증법
A1 [가정] 1h TTL이 이 API 경로(claude -p stream-json, 구독)에서 실제 적용. 검증: 첫 턴 usage.cache_creation의 ephemeral_1h 필드 또는 61분 후 cache_read > 0 (research/prompt-cache-ttl.md는 env 지원만 확인). overage면 5m이라 `--cache-ttl 5m` 폴백.
A2 [가정] 서브에이전트 호출은 메인 캐시를 갱신하지 않음(v3 §5). 검증: usage 로그로 서브에이전트 호출 직후 메인 cache_read 확인. 틀리면 U4에서 제외 규칙 변경.
A3 [가정] 3599초는 요청 지연 마진 없음. 검증: 요청 지연 p95; 필요 시 `--idle-end 3570s`.
A4 [가정] 임계값 240k/60k(v3 §4). 검증: route-log 재사용률.
A5 [가정] resume 한 세션이 TTL 안이면 캐시 적중. 검증: resume 후 첫 턴 cache_read.
A6 [가정] 입력 루프에 주기 tick을 끼울 수 있음(U5). 검증: repl.go/tui.go 루프 확인(구현 전 haiku-scout 1회).
A7 [확인 안 됨] 여러 터미널 `--model` 동시 실행 시 캐시 공유(research: 미검증). v0.8은 의존하지 않음.
A8 [가정] 레지스트리는 단일 chaude 프로세스만 씀. 다중 chaude 동시 실행 시 경쟁. 검증: 파일 락 필요 여부는 v0.9에서.
