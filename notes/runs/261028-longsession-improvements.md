## 1. 인계 실패 시 안전장치 (P0, 새 결정과 직결)
- 문제 [사실]: rotate()는 인계 턴 결과를 검증하지 않고 `note, _, _ := runTurn(handoffPrompt,false)` 후 곧바로 `sess.Close()` (repl.go:317-319). 노트가 비면 "(empty)"로 대체(repl.go:290-292)되어 이전 세션의 맥락이 최근 4턴 외에는 사라집니다. 인계 턴은 타임아웃 300초(repl.go:240)이고 interrupt 되면 노트가 부분/빈 값일 수 있습니다.
- 문제 [사실]: 새 결정으로 상한이 없어지면, 교체가 한 번 실패해도 다음 답변마다 `lastCtx > Threshold` 조건(repl.go:365)이 다시 참이 되어 270k짜리 인계 턴이 매 답변마다 반복될 수 있습니다. `start()` 실패 시 return만 하고 세션이 없는 상태로 남습니다(repl.go:327-330, 이후 handle이 nil 세션을 쓸 위험은 [추정]).
- 개선: (a) 노트 검증: 비었거나 필수 섹션(Goal, Decisions 등)이 없으면 1회 재시도, 그래도 실패하면 코드가 만드는 결정적 스냅샷(transcript.jsonl의 최근 N턴 + 파일 목록 + notes 경로)으로 폴백. (b) 새 세션 start 성공 후에만 이전 세션 Close. (c) 교체 실패/폴백 시 연속 N회까지만 시도하는 쿨다운(예: 실패 후 3답변 동안 재시도 안 함)과 사용자 알림 한 줄. (d) 조건을 `>=` 270000으로, `MaxAutoRotations`(repl.go:37,449,364)는 제거.
- 효과: 인계 소실 방지(연속성), 실패 반복으로 인한 270k 재독 비용 폭주 방지(토큰). 난이도 중.

CLAUDE.md:19는 모든 제안 답변의 마지막 줄을 `추천:` 목록으로 끝내고 첫 항목이 "ㅇㅇ" 기본 동작이라고 정했습니다. 답변이 1500자를 넘으면 `추천:`이 잘립니다 [추정: 한국어 설명 답변은 쉽게 넘음]. 교체 직후 사용자가 "ㅇㅇ"만 보내면 새 세션이 무엇에 동의했는지 모릅니다. 마지막 `trunc(joined, SnapshotChars)`(repl.go:312)도 뒤를 자르므로 최근 턴이 맨 먼저 잘립니다.
- 개선: 최신 답변은 앞 600자 + `…` + 뒤 900자로 자르고, 최신 답변에서 `추천:` 블록(마지막 `추천:` 줄부터 끝)을 정규식으로 뽑아 "## Pending default (verbatim)" 섹션으로 별도 포함(절단 제외). 24k 자르기는 섹션 단위 우선순위로(플랜 3번과 같은 방향).
- 효과: "ㅇㅇ" 단문 입력 연속성 보존. 토큰 영향 미미. 난이도 하.

## 4. 턴 타임아웃 300초가 조용히 버림 (P1)
- 문제 [사실]: `Events(300*time.Second, intr, handle)`는 타임아웃이면 false를 반환(core.go:186-187)하고, runTurn은 true일 때만 Interrupt합니다(repl.go:240-248). 즉 300초 안에 result가 오지 않으면 대기만 끝나고 child는 계속 작업 중입니다. [추정] 다음 입력의 Events가 이전 턴의 늦은 result를 자기 턴의 결과로 읽어, 응답이 한 칸씩 어긋나거나 usage/컨텍스트 값이 틀어집니다. 서브에이전트 위임(sonnet-analyst 장시간 작업)은 300초를 넘기기 쉽습니다 [추정]. 인계 턴(repl.go:317)에도 같은 한계가 적용됩니다.
- 개선: 타임아웃 시 interrupt 하지 않고 계속 대기(진행 신호가 있는 한 연장), 또는 idle 기준(마지막 이벤트 후 N초)으로 변경. 인계 턴은 별도 상한(예: 600초).
- 효과: 긴 위임 중 응답 소실/어긋남 방지. 난이도 하.

## 6. 에이전트 대기 중이면 즉시 전환 (P1, 사용자 추가 결정으로 변경)
사용자: "만약 에이전트 대기중이라면 빠르게 전환하는 방법도 있지". 처음 안(교체 연기)은 폐기하고 아래로 대체합니다.
- 문제 [사실]: 교체는 이전 child를 Close(repl.go:365-367, core.go:204-214)하며 인계 노트에는 실행 중 에이전트 정보가 없습니다. 백그라운드 에이전트의 완료 알림은 닫힌 세션으로 가 사라질 수 있습니다 [추정].
- 개선: 270k 도달 + 메인이 에이전트 완료만 기다리는 상태(답변 종료, 미완료 Agent 호출 존재)이면 기다리지 않고 즉시 교체. 인계 시 실행 중 에이전트마다 ID, 맡긴 일, 출력 경로(notes/runs/...), 시작 시각을 기록(tool_use Agent 입력과 tool_result의 agentId에서 하네스가 직접 수집 가능, 모델 토큰 불필요 [추정]). 완료 처리는 두 경로: (A) 새 세션에서 ID로 resume/SendMessage, (B) 완료 알림을 하네스가 받아 새 세션의 다음 입력에 "[agent done] ID · 결과 경로"로 전달, 알림이 안 오면 결과 경로 파일의 존재/LEDGER 항목(SubagentStop 훅이 기록)을 폴링.
- 확인 필요(미확인): (1) 새 세션(다른 session_id)에서 이전 세션이 만든 에이전트 ID로 resume 가능한가, (2) 백그라운드 에이전트가 부모 child를 Close하면 계속 실행되는가 아니면 종료되는가, (3) 완료 알림이 어느 세션으로 가는가, 닫힌 세션이면 유실되는가, (4) stream-json에서 백그라운드 완료 이벤트를 식별할 수 있는가. 이 중 (2)가 "죽는다"면 즉시 전환은 에이전트 작업을 잃으므로, 그 경우 전환 전 해당 에이전트의 결과 파일 기록 후 재시작(재위임)으로 폴백.
- 효과: 대기 시간 동안 270k 컨텍스트를 계속 유지/재독하는 비용 제거, 교체 지연 제거(토큰/속도). 난이도 중~상(실험 선행). 

(확정 261028) 완료 처리는 "이전 프로세스 유지(드레인)" 방식으로 결정됨: 이전 child를 닫지 않고 결과 파일/이벤트로 완료를 감지한 뒤 종료하며 새 세션에는 다음 입력 앞에 알림을 붙임. 상세는 plan-sonnet-conductor.md 3-1. 위 (A) resume 경로는 사용하지 않음. 이 방식의 추가 위험: 드레인 child의 권한 요청 자동 거부, 알림으로 깨어난 child의 270k 재독 비용 [추정], ledger.py에 agent_id 필요.
