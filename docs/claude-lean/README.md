# Claude Lean

**버전 0.10.1** · 버전별 변경 사항은 `CHANGELOG.md`

Claude Code에서 Opus를 메인으로 쓰면서 사용량을 크게 줄이는 설정 묶음입니다. Opus는 대화를 듣고 판단하고 설명하는 일만 하고, 파일·웹·명령 작업은 하위 에이전트(Haiku, Sonnet, 필요할 때만 Opus)가 합니다. 프로젝트마다 설치합니다.

## 어떻게 돌아가나
1. 메인 Opus가 요청을 듣고 누구에게 맡길지 정합니다. 파일 읽기·쓰기, 검색, 명령 실행은 메인에서 훅으로 막혀 있어서 항상 에이전트가 합니다.
2. 단순하고 기계적인 일(찾기, 변환, 일괄 수정, 확인, 장시간 작업 관리)은 Haiku 에이전트가 합니다.
3. 판단이 필요한 일(종합, 설계, 여러 파일 코드, 긴 문서)은 메인 Opus가 정합니다. 파일 작업은 Haiku에게 맡깁니다.
4. 결과는 메인 Opus가 일반 Opus처럼 풀어서 설명합니다.

에이전트 이름 앞부분이 실행 모델입니다(`haiku-scout`, `opus-architect`).

## 설치
| 환경 | 받을 파일 | 실행 |
|---|---|---|
| macOS (Apple 칩) | `Claude-Lean-<버전>-mac.zip` | 풀어서 `Claude Lean.app` 실행 → macOS 기본 대화상자로 폴더·작업·선택사항 선택 (서명되지 않은 앱이라 처음엔 우클릭 → 열기) |
| Windows | `claude-lean-<버전>.exe` | 실행 → 설정 창 (SmartScreen이 막으면 추가 정보 → 실행) |
| macOS·Linux 터미널 | `claude-lean-<버전>-terminal.zip` | 풀고 설치 스크립트 실행 → 색으로 구분된 질문 (폴더를 붙여 실행하면 질문 없이 설치) |

모두 Python 3이 필요합니다. 설치 후 훅이 Python으로 동작하기 때문입니다. 설치 프로그램 자체는 Python을 묶지 않고 OS 기본 기능으로 창을 띄워서 수백 KB 안팎입니다.

설치할 때 고르는 것:
- **프로젝트 폴더:** 여러 개 가능합니다.
- **작업:** 설치만 할지, 기존 대화를 정리하고 새로 시작할지 고릅니다.
- **선택사항:**
  - 메인 모델 (Opus / Sonnet)
  - 답변 방식 (설명형 / 5줄 간결형)
  - 정보 문장 메모
  - 맥락 리셋 안내
  - 대화 기록 저장
  - Sonnet·Opus → Haiku 연계
  - 설치 직후 모드

고른 값은 프로젝트에 저장되어 업그레이드해도 유지됩니다. 업그레이드는 새 버전으로 설치를 다시 실행하면 되고, 기존 설정은 백업한 뒤 병합합니다.

## 제거 (`chaude clean`)
`chaude clean [dir]`는 프로젝트에서 claude-lean 설치 파일을 제거합니다. 기본은 dry-run이라 제거 대상만 보여 주고 아무것도 바꾸지 않습니다. `chaude clean [dir] --yes`를 실행하면 바뀔 파일을 `.chaude-backup-<YYYYMMDD-HHMMSS>/`에 먼저 복사한 뒤 제거합니다. `.claude/{agents,hooks,skills}` 설치 파일, CLAUDE.md의 claude-lean 정책 블록, settings.json의 패키지 훅 항목이 대상입니다. `notes/`와 `record/`, 사용자 설정 키와 사용자 훅은 남깁니다.

## 모델별 역할과 한도
| 모델 | 에이전트 | 생각 강도 | 맥락 한도 | 한도에 가까워지면 |
|---|---|---|---|---|
| Opus (메인) | 대화·판단·설명 | low (필요한 턴만 `ultrathink`) | 자동 압축 창 150k | 리셋 안내는 선택(기본 끔, 켜면 100k·120k에서 안내). 안내는 `/exit` 후 같은 터미널에서 `claude`로 압축 없이 가벼워지고 직전 대화가 이어짐. 150k에서 자동 압축 |
| Haiku | `haiku-scout` 탐색 · `haiku-checker` 확인 · `haiku-batch-worker` 일괄 작업 · `haiku-runner` 장시간 작업 · `haiku-researcher` 웹 조사 · `haiku-drafter` 글 · `haiku-coder` 코드 · `haiku-extractor` 기록 추출 | low~medium | 자동 압축 창 100k | 자동으로 압축하고 계속 진행. 100k 창이라 Haiku 단가가 5배가 되는 100k를 넘기 전에 압축됨 |
| Opus (에이전트) | `opus-architect` Haiku 메인이 넘긴 일만 (`--model haiku` 릴레이 대상). Opus 메인은 `haiku-*`에 직접 위임하고 `opus-architect`를 부르지 않음 | high | 자동 압축 창 100k | 자동으로 압축하고 계속 진행 |

| 공통 한도 | 값 | 이유 |
|---|---|---|
| 파일 한 번 읽기 | 8k 토큰 (큰 파일은 나눠 읽음, 통째로 읽기는 훅이 막음) | 도구 결과 하나가 맥락을 크게 채우지 않게 |
| 명령 출력 / MCP 출력 | 12,000자 / 10k 토큰 | 같음 |
| Opus → 에이전트 지시 | 5줄 (Opus 에이전트에게는 대화 맥락 포함 15줄) | 지시서도 매번 다시 읽히는 분량 |
| 에이전트 → Opus 보고 | 8줄 이내, 자세한 내용은 파일 | 보고가 메인 맥락에 계속 남음 |
| 에이전트 연계 깊이 | 메인 → Sonnet/Opus → Haiku (2단계), 에이전트는 Haiku만 부를 수 있음 | 비싼 모델이 연쇄로 불리지 않게 |

## 매일 쓰는 법
| 하고 싶은 것 | 입력 |
|---|---|
| 평소처럼 지시 | 그대로 (짧아도 됨). 응답 끝 `추천:` 줄에 "ㅇㅇ"이면 그대로 실행 |
| 진행상황 보기 | "진행상황", "끝났어?" → 모델 호출 없이 표시 |
| 정보만 알려 주기 | "그 데이터는 9월 것이었어" 같은 문장 → 메모했다가 다음 지시와 함께 전달 (바로 답을 원하면 끝에 `?`) |
| 맡길 모델 정하기 | 프롬프트에 `haiku로` / `sonnet으로` / `opus로` |
| 깊게 판단시키기 | 프롬프트에 `ultrathink` |
| Opus가 직접 작업하게 | `일반모드` (되돌리기 `절약모드`, 둘 다 모델 호출 없음) |
| 예전 대화 찾기 | "예전에 마감 언제라고 했지?" → `haiku-scout`가 대화 기록 검색 |
| 맥락이 커졌을 때 | 안내가 나오면 `/exit` → 같은 터미널에서 `claude` |
| 대화 기록 읽기 | `logs/history/*.txt` (가벼운 텍스트) |

## 예상 효과
이 패키지를 만든 설계 대화(Opus 단독, 질문 67개)의 실제 기록을 같은 작업량 그대로 다시 계산한 예측입니다. 비용은 API 정가 기준입니다.

|---|---|---|
| Opus가 읽는 토큰 | 약 143만 | 약 15만 |
| 비용 | 약 $0.60 | 약 $0.12 (−80%) |

실제 효과는 작업 구성에 따라 다릅니다.
