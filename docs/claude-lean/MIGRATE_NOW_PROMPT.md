# 기존 대형 세션 → 새 세션 마이그레이션 프롬프트

## 0. 준비 (터미널에서)
`./install.sh <프로젝트 폴더>`로 먼저 설치합니다 (`APPLY_GUIDE.md` 1단계).
그다음 기존 세션을 엽니다. 닫혀 있으면 `claude --resume`으로 고르세요.
- 다시 열면 설치한 훅과 에이전트가 적용되므로, 아래 프롬프트대로 에이전트에게 맡겨집니다.
- 열려 있던 세션이라 에이전트를 찾지 못하면 직접 처리하는데, 그래도 괜찮습니다.
- 500k 세션을 다시 열 때는 첫 요청에 캐시 비용(약 $4 수준)이 한 번 듭니다.

## 1. 기존 세션에 붙여넣을 프롬프트 (한 번에, 한 턴으로)

```
migrate-session 스킬을 지금 실행해. 이 세션 자체를 지금 마이그레이션하는 작업이고, 새 작업은 시작하지 마.
1) 작업 중지. 디스크 확인은 직접 하지 말고 haiku-scout(haiku)에게 작업 폴더 목록(최종본/구버전)을, /status에게 실행 중인 작업을 병렬로 맡겨.
2) 파일 쓰기는 haiku-batch-worker(haiku)에게 내용을 넘겨서 맡겨. SESSION_HANDOFF.md를 templates/SESSION_HANDOFF.template.md 형식으로, 워크스트림(문서별/기능별/작업별)마다 섹션을 나눠 작성해. 끝난 워크스트림은 Closed에 한 줄만.
3) 대화 요약, 문서 본문 복사, 해결된 논쟁은 넣지 마. 경로로 참조해.
4) haiku-checker(haiku)로 경로 존재 여부를 검증하고, 작성한 파일 목록·워크스트림 목록만 보고하고 멈춰.
```

## 2. 세션 전환
- (선택) `/rename <프로젝트명>-legacy` — 나중에 찾기 쉽게
- 종료 후 `claude` 새로 실행
- 이전 대화는 디스크에 남아 `/resume`으로 열 수 있지만, 새 작업에는 쓰지 마세요.

## 3. 새 세션 첫 프롬프트 (워크스트림 하나만 지정)

```
CLAUDE.md를 읽고, SESSION_HANDOFF.md는 `/tmp/chaude/handoff/`로 옮긴 뒤 한 번만 읽어 "<워크스트림 이름>" 섹션만 확인하고, 읽고 나면 임시 사본을 삭제해. Source of truth 파일은 직접 읽지 말고 CLAUDE.md의 위임 규칙대로 haiku 에이전트에게 맡겨. 이전 대화를 요약하거나 끝난 작업을 다시 하지 말고, Next action 하나만 실행해.
```

다른 워크스트림은 같은 세션에서 이어서 진행하면 됩니다 (자동 압축으로 이어짐).
